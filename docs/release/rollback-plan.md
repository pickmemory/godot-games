# 回滚预案 · Steam 首发 v0.1（MC-5e）

> 归属：路远行（release-ops）。原则：**回滚是安全动作，不是失败追责**；任何值班人可依本预案发起，主理人确认执行。
> 适用：Steam depot 构建、客户端热修、存档兼容事故、商店页事故。

## 1. 触发条件（任一即启动对应级别）

| 级别 | 触发信号 | 来源 |
|---|---|---|
| **P0 回滚** | 干净机器启动崩溃率 >5%（Steam 后台崩溃报表）；或存档丢失/损坏成规模出现 | Steamworks 后台 / 讨论区 |
| **P1 热修** | 单一 Blocker（崩溃/坏档）但整体可玩；成就/云同步失效 | QA 复现 + 严守真签字 |
| **P2 观察项** | 非致命缺陷（视觉/文案/数值），不回滚，进补丁清单 | 讨论区/issue |

## 2. 构建回滚（P0）

1. **Steamworks 后台**：该 App → Builds → 选中事故构建 → **Set to previous build**（depot 级回滚，新装用户立即拿到旧构建；已装用户不受影响——见 §4 局限）。
2. 无可用旧构建时：将 `beta` 分支指向最后已知良好构建，`default` 分支公告引导用户切 beta（Opt-in）。
3. 回滚后 30 分钟内在讨论区置顶公告（模板见 §6），并通知主理人。
4. **验证**：干净虚拟机重装确认旧构建可玩 → 后台崩溃率回落 → 关闭事件（记录时间线）。

## 3. 客户端热修（P1）

1. 修复仅限 Blocker（字符串冻结豁免，见 release-checklist.md F-2）。
2. 流程：修复 → `node --check` + 浏览器/壳冒烟 → `npm run dist:win` → `--appid` 重跑 build.mjs → steamcmd 上传新构建 → 后台预览验证 → 推 default。
3. 保留完整审计：构建号、commit、变更内容、验证记录（热修简化流程，审计不简化）。

## 4. 存档兼容与坏档（P0/P1）

- 防线一：`SAVE_VERSION` 门控（`web/src/save.js` validateSnapshot）——不兼容版本**弃读不删档**，回滚旧客户端仍可读回。
- 防线二：Steam Cloud 写失败不覆盖旧档（`{ok:false}` + 退避，主进程云/镜像双写）；本地镜像 `steam-mirror/` 永不主动清除。
- 坏档个案：引导玩家退出 Steam 后启动（读镜像档）；仍坏 → Steam Cloud 版本历史（后台 Files 视图，需提前开启 Cloud 文件版本——**上线前勾选**，见 checklist C-4）。
- 升级存档 schema 时：新版本号必须向后保留读取路径或明确弃档公告，二选一并记录决策。

## 5. 商店页事故（P2→P1）

- 物料错误/文案事故：后台即时可改，无需构建；涉及分级/合规（D-3）错误 → 立即下架物料 + 主理人通报。

## 6. 沟通模板（讨论区置顶）

> 「各位玩家：我们注意到 <问题现象>。已回滚/热修为 <构建号>，Steam 客户端 <操作引导：验证文件完整性/重装>。受影响的存档可通过 <路径>。给我们一点时间，长卷未完。—— 三国长卷制作组」
