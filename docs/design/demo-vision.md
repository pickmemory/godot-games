# Demo 提升总纲 —— 「三国长卷」垂直 Demo 冲刺（MC-6）

> 2026-08-16。主创目标：**交付一个具有差异性、创新性、极具吸引力、内容丰富、探索度高、上架无侵权风险的 demo。**
> 本文档是 MC-6 阶段所有 issue 的共享上下文；执行者必读本文 + 自己的 issue。

## 一、差异化定位（不许稀释的三根柱子）

1. **亲历编年史**：玩家不是英雄，是 184 年乱世里活下来的平民。历史不改道，但你在场——
   时间轴引擎按真实编年推进世界（黄巾起事→官渡…），事件以世界状态迁移呈现（烽烟、迁界、 NPC 出场离场）。
   这是本作与一切 MC-like 的根本差异：**MC 的世界是被你改变的，我们的世界是改变你的。**
2. **中式生存美学**：十二时辰/日晷读时、火把篝火守夜、版筑夯土、粟米农耕——生存系统全部从汉代物产出发，
   不出现 MC 西幻语汇（详见 §四 侵权防线）。
3. **沙盒骨架手感**：挖掘天梯/第一夜恐惧/建造定居照搬 MC 验证过的核心循环（骨架相似是品类惯例，皮肤与灵魂是自己的）。

## 二、现状盘点（已经对的，别拆）

- 体素引擎：chunk 流式 + 面剔除 + AABB + DDA 交互，60fps 稳定
- 昼夜/天体/时辰/日晷/火把篝火点光（MC-5x 刚落地，有 11 项端到端测试守护：`tools/verify-mc5x.mjs`）
- 编年时间轴 + 章节 JSON + NPC 编年出场 + 对话树 + 任务系统 + 存档差分
- 工具天梯/农耕/建造（门窗楼梯栅栏/房屋判定→流民入住）
- 测试基建：`tools/smoke-web.mjs`（冒烟）/ `tools/repro-e-talk.mjs`（E 交谈回归，含视觉断言）/ `tools/verify-mc5x.mjs`（功能）
  无头跑法：设 `PW_CHROMIUM` 指向本机 chrome，`node tools/<脚本>.mjs`

## 四、侵权防线（上架红线，全阶段适用）

- **资产**：只用 CC0/CC-BY（禁 CC-BY-SA/GPL），`web/assets/CREDITS.md` 逐项登记来源 URL+许可；
  mmx 生成标"mmx/自研"。**D-6 做全量审计。**
- **术语**：禁用 MC 特有词（附魔/红石/下界/末影/苦力怕/经验球/ Creeper/Nether…）；中文语境用
  火把/篝火/锄地/夯土等通名。方块名、配方、UI 文案都过一遍（D-6 出排雷清单）。
- **视觉距离**：程序化像素贴图 + 体素方块本身不构成侵权（品类惯例）；规避 MC 特有 UI 形态
  （如完全相同的九宫格合成摆位/进度条样式）——我们的合成是列表式，保持。
- **名称**：正式名暂定《三国长卷 / Scroll of the Three Kingdoms》，D-7 前给出最终名清单（避开任何 MC 商标近音）。

## 六、工程铁律（每个 issue 都适用）

- 零构建 Web（ES modules + import map CDN three@0.160.0），模块只经导出签名通信
- 新方块只改 `blocks.js` 注册表 + `textures.js` 瓦片；数据驱动优先（JSON 落 `web/data/`）
- 性能分帧：结构生成/扫描类一律节流（参考 lights.js 的 0.6s rescan 模式）
- 改动必须过：`node --check` 全部 + `node tools/smoke-web.mjs` + 相关联测试
  （新增功能要补进 `tools/verify-mc5x.mjs` 或新测试脚本）
- 视觉断言教训：**状态机对了 ≠ 玩家看得见**；UI 类交付必须断言 `getBoundingClientRect` 在视口内
