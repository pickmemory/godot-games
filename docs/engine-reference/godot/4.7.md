# Godot 4.7 引擎参考 · API 缺口核对（P3-2）

> 阶段：Phase 3 · P3-2　|　角色：程基岩（engineering-lead）
> 状态：实测核对稿　|　核对版本：**Godot 4.7.1 stable**（`v4.7.1.stable.official.a13da4feb`，linux.x86_64）
> 基线锚点：`architecture.md` §13（K1~K9 缺口表）、§16（建议补本文档）；`adr-001/003/004`。
> 用途：把 §13 的 `[待 P3-2 确认]` 一次性核对成「Godot 4.7 确切用法」，供 P5 Story 直接采信，避免重复踩 API 雷区。

## 核对方法（知识诚实 · A5）

- **实测**：在 `game/` 下用 `tests/build/generate_project.gd`（headless 跑 `tests/build/setup.tscn`）调用
  `ClassDB.class_exists / class_get_property_list / class_get_method_list`、`Engine.get_version_info()` 打印结论；
  并以 `$GODOT_BIN --headless --import --quit`（exit 0，零报错）与 `--headless --quit-after 120`（运行时零报错）双重验证。
- 来源标注：`实测` = 本 issue 在 4.7.1 headless 实跑确认；`文档` = Godot 4 官方文档约定（本 issue 未单独实测的细节）。
- 凡本 issue 未实测、且实现细节会影响代码正确性的，标 `[待核]`，**不臆造**。

### K10 · class_name 与 Autoload 同名冲突（本 issue 新发现）  ★ 修订 issue 验收

| 项 | 结论 |
|---|---|
| 4.7 实际 | `class_name EventBus` 写在注册为 Autoload `EventBus` 的脚本上 → **硬解析错误**「Class "EventBus" hides an autoload singleton」（不再是旧版警告）；该 Autoload 创建失败 |
| 来源 | 实测：首次 `--headless --import --quit` 报此错；移除 `class_name` 后通过 |
| 影响 | issue #10 验收项「空壳脚本含 class_name」**在 Godot 4.7 下对 Autoload 脚本不可行** |
| 修订动作（本 issue 已采） | **Autoload 脚本不加 `class_name`**（EventBus/DynastyLoader/SaveManager 以注册名作为全局句柄，class_name 冗余）；非 Autoload 脚本（Player/WorldDirector/PlayerMovementGlobals/TestGround/Boot）保留 class_name |
| **待主创审批** | 是否接受「Autoload 脚本去 class_name」偏离验收项；若坚持要 class_name，唯一可行解是 class_name 与 Autoload 注册名**不同名**（如 `EventBusImpl`） |

## 关键工程发现（非 §13 条目，但影响实现）

### F-i · InputMap 持久化必须走 `input/*` 设置（非 InputMap 单例）

`ProjectSettings.save()` **只序列化 ProjectSettings 属性库**，**不读取** `InputMap` 单例的运行时态。故持久化 InputMap 必须：
`ProjectSettings.set_setting("input/<action>", { "deadzone": float, "events": [InputEvent, ...] })`，
Godot 在 `save()` 时把 `events` 内的 `InputEvent` 序列化为权威 `Object(InputEventKey/JoypadMotion/JoypadButton, "prop":val, ...)` 内联格式，启动时从 `[input]` 段装载回 `InputMap`。
> 本 issue 的 `tests/build/generate_project.gd` 即用此方式权威产出 `[input]`（避免手写易错的 Object 内联格式）。

### F-ii · InputEvent `device` 须显式设 `-1`（任意设备）

代码 `InputEventKey.new()` 默认 `device` 在序列化时曾出现异常值（`16`），与物理键盘事件（device 0）不匹配会导致按键不触发。
**约定**：所有 InputMap 事件显式 `device = -1`（任意设备，与编辑器录入惯例一致）。本 issue 38 个事件均已 `-1`（`grep '"device":-1'` 计 38）。

### F-iii · `change_scene_to_file` 在 `_ready` 须 `call_deferred`

`boot.gd._ready` 直接 `get_tree().change_scene_to_file(...)` 触发「Parent node is busy adding/removing children」错误（场景树仍在添加节点）。
**约定**：`get_tree().call_deferred("change_scene_to_file", path)`。本 issue 已采。
